Verify the release:
  helm test {{ .Release.Name }} --namespace {{ .Release.Namespace }}

Nothing about a map reaches this pod. The map lives in the .ddd file the visitor
exports and the model in its .ddm, and the tool keeps a copy of both in their
browser's local storage — this side of it holds neither. A pod can be deleted at
any moment without losing anybody's work.

Work that was never exported lives in that one browser, which is what the unload
warning is for: a copy in one browser is insurance, not an artefact.

Reminder: image.tag is pinned with pullPolicy: Never in values-local.yaml, so a
rebuilt image under the same tag leaves the running pods untouched. After
rebuilding, force them over:
  kubectl rollout restart deployment/{{ include "ba-cm.fullname" . }} -n {{ .Release.Namespace }}

or just run helm/ba-cm/deploy.sh, which does all three steps.
